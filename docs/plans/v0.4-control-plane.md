# v0.4 Control-Plane Implementation Plan

Task: `agent-process-kit-product-redesign-20261008`

Contract: [`docs/architecture/full-train-control-plane.md`](../architecture/full-train-control-plane.md)

Target release: `v0.4.0`

Status: approved for implementation after one plan-review round and targeted blocker verification

## Outcome

Ship Agent Process Kit as an installable, dependency-free Node.js control plane that carries a normal coding request through durable intake, conditional clarification, reviewed specification and plan, parallel ATDD/TDD work, bounded code review, real local UAT, authorized release and production proof. The operator speaks in ordinary task language. Host adapters and one broad orchestration skill translate that language into the same canonical commands.

The implementation is complete only when the machine plan at [`plans/v0.4-control-plane.json`](../../plans/v0.4-control-plane.json) reports every required story current for one candidate, every mandatory clean-install Codex and Claude scenario has a current receipt, protected `main` CI passes, and the `v0.4.0` tag and release assets read back to the exact main commit. A missing mandatory host receipt keeps CP-015 incomplete. Removing a host or scenario from the support promise requires an explicit product decision and contract generation; a limitation note cannot convert missing proof into a pass.

## Locked depth

- Mode: `full-train`, because this is a multi-story control-plane and host-integration release.
- Review cap: one independent plan review and one independent code review. Self-checks do not create extra independent rounds. Fixes receive targeted verification only.
- In scope: canonical task state, transitions, candidate identity, evidence freshness, fenced leases, story graph, execution grants, external-attempt reconciliation, exact session binding, checkpoint/handoff, status, completion eligibility, CLI, setup/rollback, Codex and Claude adapters, synthetic end-to-end trains, docs, migration and release proof.
- Included cleanup: migrate useful v0.2 runtime primitives into the new module boundaries; replace manual skill choreography in the public path; remove statements that the product has no runtime after the runtime exists.
- Non-goals: browser engine, deployment platform, issue tracker, hosted coordinator, telemetry product, hostile-process isolation, model-correctness guarantee, marketplace-native plugin, private FanEmpire paths or provider commands.
- Deferred hardening: Windows host UAT, remote/shared state backend, graphical dashboard, marketplace distribution, more than two host adapters, automatic global-config editing.
- Blocking findings: duplicate external effect, lost canonical state, stale writer accepted, unrecoverable handoff/checkpoint, security boundary bypass, required real path silently skipped, wrong candidate accepted, or broken install/release path.
- Checkpoints from this plan: core vertical slice 90 agent-minutes; continuity and external-effect slice 180 minutes; host E2E and full gate 300 minutes; release-readiness decision 360 minutes. If a checkpoint slips, cut optional host polish and examples before any invariant or proof path.

## Implementation decisions

1. **Runtime shape.** Use dependency-free Node.js ESM on Node 22, matching v0.2. Keep public records JSON-serializable and validate all external input at the boundary. Do not add a build step or TypeScript migration in v0.4.
2. **One canonical record.** Each task has one atomically replaced record with `recordVersion`. Large/versioned artifacts live beside it and are referenced by digest. Journals are human projections, not canonical lifecycle state.
3. **Compare-and-swap writes.** Every canonical mutation checks `recordVersion`, `leaseId`, `fenceToken`, lease scope, spec generation and plan generation in one lock. The store increments the record version on commit.
4. **Content identity.** `contentFingerprint` is a canonical hash over Git tracked content plus relevant untracked files and exclusions recorded in the receipt. Commit SHA and package digest enrich identity; they never replace the working-content hash.
5. **Evidence freshness.** A receipt declares full-candidate or scoped coverage. Full receipts stale on any content change. Scoped receipts remain current only when the impact adapter proves changed paths and contracts are disjoint; unknown impact stales them.
6. **One integration writer.** Story workers can hold disjoint story/worktree leases and submit immutable results. Only the canonical task lease advances phases, generations and artifact pointers. `completeTask` requires that integration lease, rejects every outstanding worker lease and execution grant, commits `complete`, then retires its own integration lease in the same atomic mutation.
7. **External effects.** Operator intent and executable grants are separate. Grants bind exact candidate, target, action, generation, expiry and use count. Unknown provider outcomes enter reconciliation before any retry.
8. **Host integration.** Setup writes only hash-owned project-local files and managed instruction blocks. It produces host-specific hook/config instructions where native automatic registration is unavailable. Host UAT reports registration and behavior separately.
9. **Automatic method selection.** A renamed broad orchestration skill is the natural-task trigger. Existing craft skills remain bundled internal methods and independently installable. The CLI, hooks and skill all call the same command layer.
10. **No simulated production truth.** Synthetic providers can prove orchestration. They cannot satisfy a production receipt. Release fixtures explicitly distinguish local, pushed, deployed and production-verified states.

## Executable stories

### CP-001 — Schemas and lifecycle model

- Owns: record and artifact schemas, task modes, status/phase enums, transition matrix, command input validation.
- Files: `runtime/core/schema.mjs`, `runtime/core/transitions.mjs`, `runtime/schemas/*`, `tests/core/transitions.test.mjs`.
- Prerequisites: contract frozen for implementation.
- Parallel boundary: must land before all other core stories; no state I/O.
- RED: table-driven tests reject every unspecified status/phase transition, illegal resume of terminal states and skipped required gates.
- GREEN: schema validation and pure transition functions cover every contract row and mode-specific skip rationale.
- ATDD/UAT: CLI fixture attempts pause/resume/cancel/close and receives stable machine errors.
- Gates: schema examples parse; transition mutation score covers valid and invalid rows; `node --test tests/core/transitions.test.mjs`.
- Artifacts: schema digest, transition coverage receipt.
- Recovery: schema version remains `1`; incompatible draft data is discarded before public release.

### CP-002 — CAS task store and immutable artifacts

- Owns: safe state paths, private permissions, durable atomic JSON, per-task lock, `recordVersion` CAS, append-only artifact manifest.
- Files: `runtime/core/store.mjs`, `runtime/core/artifacts.mjs`, `tests/core/store.test.mjs`.
- Prerequisites: CP-001.
- Parallel boundary: single owner of store; other stories consume its test fixture API.
- RED: concurrent writers with the same expected version race; one must fail. Symlink, truncated temp, dead lock and digest mismatch fixtures fail safely.
- GREEN: exactly one CAS succeeds, directory/file fsync completes, artifacts are content-addressed and manifest pointers advance atomically.
- ATDD/UAT: crash between artifact write and pointer update recovers to the prior canonical record with orphan reporting.
- Gates: core store tests under repeated concurrency; permission and path checks on macOS/Linux fixture semantics.
- Artifacts: store recovery receipt and compatibility note.
- Recovery: repair command reports orphan/temp/lock state and never deletes a live writer's files.

### CP-003 — Candidate identity and evidence freshness

- Owns: Git/worktree fingerprint, relevant untracked content, environment identity, receipt coverage and invalidation.
- Files: `runtime/core/candidate.mjs`, `runtime/core/evidence.mjs`, `runtime/adapters/git.mjs`, `tests/core/evidence.test.mjs`.
- Prerequisites: CP-002.
- Parallel boundary: isolated from lease/story code; exposes pure identity and freshness API.
- RED: amend/rebase with identical content stays equal; tracked or relevant untracked change invalidates full evidence; unknown scoped impact stales receipt; wrong deployed revision fails.
- GREEN: deterministic canonical fingerprints and explicit impact verdicts bind all evidence subjects.
- ATDD/UAT: run a real temporary Git repo through dirty, commit, amend, scoped-change and package-digest scenarios.
- Gates: fixture portability; no ignored secret content is read or emitted; hashes stable across path enumeration order.
- Artifacts: candidate identity vectors and evidence invalidation receipt.
- Recovery: unsupported VCS or unreadable worktree yields `identity-unavailable`, never a guessed candidate.

### CP-004 — Fenced leases and writer ownership

- Owns: canonical/story leases, monotonic fence tokens, renewal, expiry, revocation and stale-writer rejection.
- Files: `runtime/core/leases.mjs`, store mutation-context checks, `tests/core/leases.test.mjs`.
- Prerequisites: CP-002.
- Parallel boundary: owns lease records only; integrates with stories and handoff through commands.
- RED: expired sender and new receiver both mutate the same version; stale sender must always lose even when it writes first after transfer.
- GREEN: acquisition increments fence per scope; every mutation validates lease, scope, fence, version and generations atomically.
- ATDD/UAT: two real Node processes contend for canonical and disjoint story scopes.
- Gates: repeated race test; clock injected for expiry/renewal; no wall-clock sleeps.
- Artifacts: fencing race receipt.
- Recovery: reconciliation names live owner, expired owner and next safe acquisition; no automatic live-lock deletion.

### CP-005 — Story graph and integration eligibility

- Owns: story DAG validation, readiness, claims, immutable results, one integration writer and bounded review/fix stories.
- Files: `runtime/core/stories.mjs`, `runtime/schemas/story-graph.schema.json`, `tests/core/stories.test.mjs`.
- Prerequisites: CP-002 and CP-004.
- Parallel boundary: workers only write story result artifacts; integration mutation remains canonical-owner-only.
- RED: cycles, duplicate ownership, unmet dependencies, overlapping mutable paths and second integration writer are rejected.
- GREEN: deterministic ready set, claim/release, immutable submission, receipt freshness and integration completion.
- ATDD/UAT: three stories run with two independent lanes and one integration lane; blocked lane does not stop an unrelated ready lane.
- Gates: graph/property fixtures; review cap enforced in fix-story creation.
- Artifacts: story graph and progress-ledger receipt.
- Recovery: abandoned claim expires through CP-004 and returns story to ready without mutating submitted artifacts.

### CP-006 — Scoped grants and external-attempt reconciliation

- Owns: operator intent, execution grants, use count, revocation and external-attempt state machine.
- Files: `runtime/core/grants.mjs`, execution-grant schema, `tests/core/grants.test.mjs`.
- Prerequisites: CP-002, CP-003 and CP-004.
- Parallel boundary: no provider implementation; adapters submit intent/attempt/readback facts.
- RED: old grant after candidate/generation/target/pause change, double use, blind retry after timeout and action outside target all fail.
- GREEN: exact grants expire/revoke deterministically; attempts persist intent before execution and require reconciliation for unknown outcomes.
- ATDD/UAT: fake provider records one external write, loses the response, then readback reconciles it without a second write.
- Gates: idempotency-key uniqueness; pause/cancel/rollback revocation; concurrency race on `maxUses`.
- Artifacts: grant and reconciliation receipts.
- Recovery: unknown attempts block the owning external action only; independent local work may continue.

### CP-007 — Completion eligibility and status projection

- Owns: phase gates, required evidence by mode/boundary, stale/missing proof, delivery contour and operator-facing status.
- Files: `runtime/core/eligibility.mjs`, `runtime/core/status.mjs`, `tests/core/eligibility.test.mjs`.
- Prerequisites: CP-001 through CP-006.
- Parallel boundary: pure query layer over canonical records and verified artifacts.
- RED: green tests without local UAT, push without deploy, deploy of wrong revision, unreconciled attempt, active worker lease, active execution grant and stale receipt all block completion with exact reasons. A valid integration lease must not block the completion mutation that owns it.
- GREEN: `canAdvance`, `canComplete`, `getStatus`, `getEvidence` and `getDeliveryState` return stable structured verdicts; `completeTask` atomically commits the terminal state and retires its integration lease.
- ATDD/UAT: Russian `дай статус` projection shows goal, lanes, denominator, last trace, stale/missing proof, pending decisions, next owner and action.
- Gates: snapshot tests cover quick/standard/full-train and local/commit/push/deploy/production boundaries, a passing completion with only the integration lease, and failures with any worker lease or execution grant.
- Artifacts: eligibility vector and status projection receipts.
- Recovery: malformed receipt is quarantined and reported as missing evidence; it never crashes the query path.

### CP-013 — v0.2 state migration and rollback

- Owns: detect/import v0.2 explicit bindings and open handoffs, journal acceptance projection, dry-run report, reversible migration receipt.

- Prerequisites: CP-008, CP-009 and CP-012.

The v0.4 writer lease is acquired only after that sequence completes.

- Artifacts: migration and rollback receipts.
- Recovery: partial migration resumes by receipt phase. Rollback requires no active v0.4 writer, grant, attempt or post-import mutation; it removes the tombstone and restores the quarantined root without starting any host. Foreign edits or an active v0.4 owner block rollback. Legacy ownership is never reactivated automatically.

## Verification layers

1. **Pure core tests:** schemas, transitions, CAS, leases, identities, freshness, story DAG, grants, eligibility.
2. **Process integration tests:** concurrent writers, crash windows, exact binding, handoff, checkpoint, setup transaction and migration.
3. **Synthetic provider tests:** external effect reconciliation, release/deploy revision, authenticated-environment identity and observation windows.
4. **End-to-end CLI trains:** natural clear and ambiguous tasks, bounded review/fix, local UAT failure, parallel integration and completion boundaries.
5. **Real host UAT:** fresh Codex and Claude installs each prove natural task, continuation after compaction, fresh-chat status, pause/resume and terminal cancellation. Host-native registration is a separate receipt from runtime behavior. A missing mandatory receipt blocks the release.
6. **Release proof:** protected CI, exact main commit, tag target, packed files, checksums, downloaded assets and rendered onboarding.

No test may pass by directly mutating the canonical JSON file. Test helpers use the same commands as production callers, except corruption/recovery fixtures that deliberately construct invalid state.

## Plan review protocol

The single independent reviewer checks only:

- contract coverage and dependency order;
- whether a story can falsely pass without the user-visible or safety behavior;
- unsafe parallel ownership or migration/release gaps;
- any blocker-class omission.

Accepted blockers are fixed in this plan and machine graph, then receive targeted self-verification. There is no second full plan-review round.

## Release boundary

Implementation work may proceed autonomously through local UAT and release readiness. Publishing `v0.4.0` is already inside the operator-confirmed product train, but the release adapter must still prove that the exact protected-main candidate is the one tagged and published. Any provider result that is unknown is reconciled before retry.

The release receipt must contain:

- final content fingerprint and commit SHA;
- protected PR/merge identity and post-merge CI URL;
- `v0.4.0` tag target;
- npm/package archive digest when published;
- GitHub source and `.skill`/runtime asset digests;
- downloaded-byte checksum verification;
- clean remote discovery/install result;
- Codex and Claude host UAT receipts or precise missing proof;
- rendered README receipt;
- known limitations and owned follow-ups.
